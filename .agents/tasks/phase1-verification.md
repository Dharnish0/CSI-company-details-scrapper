## What changed, per item

1. **Schema.** `schema.sql` restored from git (263 lines, 17 tables, `IF NOT EXISTS`, identical to HEAD DDL which already contained all newer columns; no column existed in the live DB that HEAD lacked, verified by `scripts/diff_schema.py`). `runs.status` CHECK now also allows `PARTIAL`. `db/connection.py: migrate_db` rebuilds `runs` in place for older DBs after a consistent file backup (`<db dir>/backups/<name>-<UTC>-premigrate.db`), rows copied unchanged, no-op on the second run. Tests in `tests/test_db.py`: fresh init passes `verify_db`, columns equal the live DB copy, idempotent, migration preserves rows and creates one backup.
2. **Groq structured output.** Root cause: with tools the provider omitted `response_format` AND never put the schema in the prompt, so the model invented `results` instead of `assessments`. Now the schema is always in the system prompt; `json_schema` is used without tools (400 on it falls back once to `json_object`); with tools, `tools` and no `response_format`. `reasoning_effort:"none"` only for Qwen3 models (dropped if rejected). `AgentRunner` offers tools only while the agent still has tool budget and never on the REPAIR turn, so the final answer is tool-free. Pydantic validation and the single repair are unchanged. Tests: `tests/unit/test_groq_provider.py` (posted body via `provider.complete`), `tests/agents/test_relationship_tool_schema.py` (RelationshipAgent: valid first try, `results`→repaired, tool-free continuation).
3. **429 handling.** `RequestPacer` (min spacing from `LLM_RPM_LIMIT`, 60 s token window from `LLM_TPM_LIMIT`, `x-ratelimit-*` hints, 429 penalty). Groq default is 30 RPM, no client token cap (limits vary by plan; headers decide). `Retry-After` is honoured in full up to `LLM_RETRY_AFTER_CEILING_SECONDS` (120); beyond it the call returns a retryable failure carrying `retry_after_s`. 429 retries (`LLM_RATE_LIMIT_RETRIES`=5) are separate from 5xx retries, do not count as provider requests and do not open the breaker; 401 still does. `GatewayFailure` and `AgentError` gained `retryable` and `retry_after_s`. Tests: `tests/unit/test_gateway_ratelimit.py` (FakeClock).
4. **Queue recovery.** A retryable failure with attempts left makes the task return `RETRY_LATER`: candidates are saved (decision `REVIEW`, reason `VERIFICATION_RETRY_PENDING`/`EXTRACTION_RETRY_PENDING`), no entities are created, the supervisor reschedules with `not_before = now + max(Retry-After, QUEUE_RETRY_BASE_SECONDS*2^(attempt-1))` and keeps `attempts`. Short waits (<= `QUEUE_RETRY_WAIT_MAX_SECONDS`) are slept in-process, longer ones pause the run (`RETRY_WAITING`, resumable). On the last attempt (`QUEUE_MAX_ATTEMPTS`=3) the existing behaviour applies per candidate: `REVIEW_REQUIRED`/`VERIFICATION_UNAVAILABLE`, task finishes DONE with note `PARTIAL:...`. Only verified (CONFIRMED) children are enqueued; `recurse_into_review` untouched. Verification-unavailable is now per failed batch, not per task. Tests: `tests/test_queue_recovery.py`.
5. **Run status.** `RunStatus.PARTIAL` added. On an empty queue the status is derived from the DB: FAILED (root task failed, or tasks failed and none finished), PARTIAL (any FAILED task or DONE task with a `PARTIAL:` note), else COMPLETED. `MAX_TASKS` keeps RUNNING, breaker/`RETRY_WAITING` give PAUSED, budget stays `BUDGET_EXHAUSTED` in the DB and is shown as `BUDGET_STOPPED` (`run_status_label`). CLI exit codes: COMPLETED 0, FAILED 1, usage 2, other non-final 3, PARTIAL 4. Excel Summary shows the label, failed tasks and tasks finished with gaps.
6. **Gemini.** Rewritten on `google.genai` errors (`APIError` code 429/5xx retryable with parsed `retryDelay`, 401/403 auth, other 4xx not retryable), `ThinkingConfig` (`thinking_budget=0` for Gemini 2.x, `thinking_level=MINIMAL` for newer), `GEMINI_THINKING=off|low|default`, `request.reasoning` honoured, thought parts excluded, `thoughts_token_count` added to `tokens_out` and `metrics.thoughts_tokens`, finish reasons mapped (`MAX_TOKENS`→`length`), `response_json_schema`, HTTP timeout, automatic function calling disabled, output cap raised when thinking is allowed, one retry with the lowest thinking level if the API rejects the setting. Fake-client tests, no network. The earlier 142 s / `finish_reason=length` result still has to be re-tested live; the cause is not asserted until `thoughts_tokens` is observed in a real response.
7. **Registry.** `discover_ollama` (`GET /api/tags`, 2 s timeout), one entry per installed model, an unavailable placeholder when the server is unreachable or empty, a configured-but-missing model listed unavailable with `ollama pull`, no Ollama entry derived from a cloud `LLM_MODEL`. `run --provider ollama --model X` exits 2 unless X is installed. `llms` shows `[n]` numbers equal to the menu numbers and `[-]` for unavailable. New `OLLAMA_BASE_URL`.
8. **Also fixed.** `report` restored to the calibration report (the stub printed `root_url` as status) with provider/model, status label, per-agent ok/failed/failure rate/failure kinds/tokens, task gaps. `verify` runs `verify_db` plus `data_quality.check_run` (exit 1 on any FAIL). `app.provider_settings_for_run` replaces the groq-only ternary and forwards every setting. The CLI menu is used only on a terminal; without one it uses the configured settings (and `--yes` for billable providers), so scripted runs cannot block on `input()`.
